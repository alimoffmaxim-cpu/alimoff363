# Отчёт «Директ + Тильда»

Новый клиент (ноябрь 2026), единственный источник рекламы — Яндекс Директ. Код — `direct-tilda/` в ветке
`claude/kind-cannon-kebl4w` (перед работой `git pull`). Правила репозитория — `CLAUDE.md`; устройство и установка —
`direct-tilda/README.md`. По-русски, коротко.

**Решения пользователя:** UTM-метки в объявлениях клиента **менять нельзя** — сопоставление обязано понимать любые;
доступ к Директу — OAuth-токен аккаунта клиента (`YANDEX_TOKEN`, `YANDEX_LOGIN` только для агентского);
заявки — вебхуком Тильды в `doPost` (веб-приложение, ключ `TILDA_SECRET`); новая отдельная Google Таблица.
Как у «Совы»: обновление в 01:00 по Москве за вчера, «по» по умолчанию вчера и сбрасывается при открытии,
НДС 22 %, без эмодзи в названиях листов.

## Файлы

| Файл | Что |
|---|---|
| `1_main` | `DR`, `DR_SHEETS`, меню «Отчёт», `drDailyUpdate` (триггер), `onEdit` (B3/D3 «Сводной» → пересчёт), статус H2 |
| `2_util` | даты (`drKey_` → 'yyyy-MM-dd' по Москве), листы, `drWrite_` |
| `3_direct` | токен, Reports API `AD_PERFORMANCE_REPORT` → «Данные Директа», `ads.get` → «Тексты объявлений» |
| `4_tilda` | `doPost`/`doGet`, разбор UTM (поля → кука TILDAUTM → параметры `landing_page`), код для сайта, меню подключения, тестовая заявка |
| `5_match` | справочник объявление→группа→кампания, правила, `drMatch_` (правило → ID → название), `drMatchAll_` пишет N–T «Заявок» |
| `6_report` | период, `drRecompute_`, «Сводная» (итоги, сравнение, источники, по дням) |
| `7_tables` | «Кампании», «Группы», «Объявления»; строки «(без группы)», «(без объявления)», «Директ, заявки без привязки» — итоги всех листов сходятся |
| `8_setup` | создание листов, поля периода, правила-подсказки, проверка недостающих файлов |

Цифры листов отчёта — **значения, считает скрипт** (не формулы): нет проблем с локалью; пересчёт — после загрузки,
при смене дат, из меню. Простые триггеры ограничены 30 с.
