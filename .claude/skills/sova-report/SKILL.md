# Отчёт «Сова»: полный контекст

Пользователь — специалист агентства, ведёт рекламу клиники «Сова» (Саратов, Волгоград) в VK Рекламе
через eLama. Общаться **по-русски**, коротко и по делу; правила репозитория — в `CLAUDE.md` (обязательны).
Код живёт в ветке **`claude/kind-cannon-kebl4w`** (в ветке по умолчанию `claude/trusting-turing-vrdq0i`
папки `sova-report` нет — там лендинг мотошколы). Коммитить и пушить сюда же. В эту ветку пишут
несколько сессий: **перед работой `git pull`**, перед push — `git pull --rebase`.

## Как устроена таблица

Листы: **Сводная**, по листу на направление, **⚙ Настройки**, **Данные**, **Волгоград РК**. Сейчас направлений 5:
Сова (Саратов), Совенок (Саратов), Сова комфорт (Саратов), Волгоград (Сова), Волгоград (Стационар).
Все цифры — **формулы из «Данные»** (1 строка = 1 день одного направления: дата, направление, расход, показы,
клики, подписки). Подписки = вступления в сообщество, метрика `base.vk.result`.

**«⚙ Настройки»**: A2:A… — направления подряд до первой пустой строки (`#` в начале — пропуск);
B — статус подключения; C — своя метрика подписок; D — цвет. **F2** = `TODAY()-1` — отчётная дата (вчера),
на неё ссылается E3 всех листов. **F4/F5** — «Последнее обновление данных» и статус последнего запуска.

**Листы «Сводная» и направлений, верх:**
- E3 — отчётная дата (вчера). **H3** — «Период с» (ввод, пусто — с 1-го числа месяца), **J3** — «по»
  (по умолчанию формула `=$E$3`, можно поставить дату). H4 — подсказка.
- Строки 5–9 — блок периода: K7/L7 — даты «с»/«по», строка 8 — сравнение (свой период — с предыдущим той же
  длины, иначе этот месяц с теми же днями прошлого), строка 9 — изменение с ▲/▼.
- **Колонки метрик везде одинаковые:** A подпись, **B расход, C расход с НДС (×1,22), D показы, E клики,
  F CTR, G CPC, H подписки, I цена подписки, J CR в подписку**; в блоке периода K, L — даты.
  CPC и цена подписки — от расхода **без** НДС.
- Графики — в одну колонку с колонки **N** (подписки, под ними расход за те же периоды).

**«Сводная»** ниже блока периода: таблица направлений за период (строка 13…, «Доля расхода» в K), затем
с строки `15 + число направлений` — тенденция: подписки / цена / расход по направлениям по неделям и по
месяцам (+ «Итого», «К прошлой», «Тенденция» с 4 периодов), 6 графиков.

**Лист направления** с 11-й строки: постоянная таблица **по неделям** + строка «Разница с прошлой неделей»,
постоянная **по месяцам** + «Разница с прошлым месяцем», затем таблица **по дням** выбранного периода
(начало — `sbDayRow_ = 11 + (недель + 4) + (месяцев + 4)`), 3 графика.

**«Волгоград РК»** (`12_volgograd.gs`, не формулы — значения, пишет скрипт): строка = одна кампания за неделю
или месяц. Кампании — все из кабинетов, чьё направление совпадает с `SOVA_VLG.CABINET_REGEX` («Волгоград (Сова)», «Волгоград (Стационар)»), из остальных — с `volg` / `vlg` в названии или номер в `SOVA_VLG.IDS`; уровень — `ad_plans` (РК нового кабинета), запасной — `campaigns`. Меню показывает итог по каждому кабинету;
с `SOVA_VLG.FROM` (01.08.2026). Колонки: A «Период» (`45 неделя 2026` — ISO-номер, как у клиента; `Ноябрь 2026`), B тип,
C начало, **D–N = колонки A–K таблицы клиента** (Номер РК, Название РК, Куда ведем — `subscri`/«подпис» → «подписка», иначе
«активности», Бюджет, Показы, Клики, CTR, CPC, Пдп/активности, Стоимость пдп, CR в пдп), O направление, P время обновления.
Пересобирается после каждой загрузки (`sovaSyncAll_`) и из меню. В таблицу клиента — `IMPORTRANGE` + `QUERY ... where Col1 = '45 неделя 2026'`
(формула — в README, раздел «Волгоград → таблица клиента»). Стенд этот лист не проверяет (нужен VK API).

## Поведение (решения пользователя — не менять без просьбы)

- Недели (пн–вс) и месяцы — **с недели 21.09.2026** (`SOVA.TRENDS_FROM`) до последнего завершённого,
  **вся история хранится** (предохранитель 520 недель / 120 месяцев). Подписи с годом: «21.09–27.09.2026», «Сентябрь 2026».
- Постоянные таблицы недель/месяцев перестраиваются **только после загрузки данных**, выбор периода их не трогает;
  при росте сдвигают всё ниже (ничего не затирают). Скрипт чистит колонки A–L ниже 10-й строки — свои пометки туда нельзя.
- **Автообновление раз в сутки в 01:00 по Москве** (`UPDATE_HOUR`, `TIMEZONE`, триггер с `inTimezone`),
  загружает **по вчера**; последние 3 дня перезагружаются (VK досчитывает). Результат пишет в «Настройки»!F5;
  в шапке листов «⚠ данные не обновлялись…», если нет позавчерашнего дня.
- **«По» по умолчанию вчера; при каждом открытии таблицы снова вчера** (`sbResetPeriodEnds_` в onOpen), «с» сохраняется.
- **Даты на «Сводной» копируются на все листы направлений** (onEdit → `sbCopyPeriod_`).
- НДС 22% (`VAT_PERCENT`). Месяцы — полными названиями.
- В названиях листов/меню **без эмодзи совы**.
- Токен кабинета хранится в Свойствах скрипта **по названию направления** — переименовали направление → подключать заново.

## Правила кода (наступали — не повторять)

- **Локаль ru_RU: формулы пишутся с запятыми и обязательно проходят `sbLocF_` / `sbLoc_`** (они переводят «,»
  в «;» после проверки локали). В формулах **нет десятичных дробей** (`1/200`, `*(100+22)/100` вместо `0.005`, `1.22`).
- Порядок файлов не важен: на верхнем уровне только литералы; зависимости от других файлов — в функциях или геттерах (`SB.D`, `SB.SET`).
- Колонки заданы буквами во многих местах (`sbDerived_`, `sbMetrics_`, `sbKpi_`, сводная, `sbDirTables_`, графики `[8]`, `[2]`, `[9]`,
  python-шаблон). Сдвигаешь колонку — ищи все (`grep -n "'BCDEFGHIJ'\|\\$K\\$7\|\\$L\\$7"`), и прогоняй стенд.
- Простые триггеры (onOpen, onEdit) — лимит 30 с; тяжёлое делать в меню или в триггере по времени.
- Файлы ~100–150 строк; секретов в коде нет.
- После правки `.gs`: стенд → пересобрать xlsx (`python3 sova-report/tools/build_xlsx.py sova-report/sova-report.xlsx`)
  → страница с кодом (`python3 tools/copy_page.py sova-report <scratchpad>/sova-code.html --title "Код отчёта «Сова»" --final "…"`,
  опубликовать тем же путём/по тому же url) → README → коммит и push в `claude/kind-cannon-kebl4w`.

Стенд собирает все `.gs`, гоняет их в имитации Google Таблиц (`mock.js`, русская локаль, пересборка),
пересчитывает формулы в LibreOffice и сверяет с «Данными» (`verify.py`): недели/месяцы подряд, суммы, «Разница»,
дни периода, НДС. Должно быть «ИТОГ: всё совпало» в каждом сценарии. Графики стенд видит только как диапазоны —
вид проверяют глазами после пересборки у пользователя. Перед выводами о «реальной» таблице — прочитать её через коннектор.

## Типичные проблемы пользователя

- **«Не удалось открыть файл» в Apps Script** — в Chrome несколько Google-аккаунтов (`authuser=N`). Работать в окне,
  где вошли только в `alimovagencytech@gmail.com` (инкогнито / отдельный профиль).
- **`SyntaxError` в каком-то файле** — вставка легла поверх старого кода. В файле Cmd+A → Delete → вставить заново → Cmd+S.
  Пока есть ошибка, проект не сохраняется («Несохраненные изменения»).
- **`X is not defined`, `getRange(… null …)`** — не хватает файла или файлы разных версий. Проще всего заменить все 11.
  Сборка сама называет недостающие файлы (`sbMissingFiles_`).
- **`#ERROR!` везде** — формула записана без `sbLocF_`.
- После любой замены кода: обновить таблицу → **Сова → Создать / пересобрать отчёт**; после смены расписания —
  **Сова → Включить автообновление** (иначе остаётся старый триггер).
- «Удалить все строки с листа «Данные»» стирает историю: из VK заново грузится только 365 дней.
