# Отчёт «Директ + Тильда» → Google Таблица

Расход, показы и клики — из **Яндекс Директа** с разбивкой по **кампаниям, группам и объявлениям**.
Реальные заявки — с сайта на **Тильде** (вебхук), каждая сопоставлена с кампанией, группой и объявлением
по меткам. Видно, какое объявление сколько стоило и сколько заявок дало.

| Лист | Что на нём |
|---|---|
| **Сводная** | Период «с» (B3) и «по» (D3, по умолчанию вчера, при открытии таблицы снова вчера). Итоги за период и сравнение с предыдущим периодом той же длины; заявки по источникам (до объявления / до группы / только кампания / Директ без привязки / другие источники / без меток); таблица по дням. Статус последнего обновления — H2 |
| **Кампании**, **Группы**, **Объявления** | За период со «Сводной»: расход, расход с НДС, показы, клики, CTR, CPC, заявки, цена заявки, CR в заявку. У объявлений — заголовок, текст и ссылка. Сверху «Итого», сортировка по расходу |
| **Заявки** | Каждая заявка с Тильды: время, форма, имя, телефон, email, utm-метки, страница входа — и результат: источник, кампания, группа, объявление, **как сопоставлено** |
| **Сопоставление меток** | Ваши правила для меток, которые скрипт не понял сам |
| **Данные Директа** | 1 строка = 1 день одного объявления (из Reports API) |
| **Тексты объявлений** | Заголовки, тексты, ссылки объявлений (из API) |

Метрики: CTR = клики / показы, CPC = расход / клики, цена заявки = расход / заявки из Директа,
CR = заявки / клики. Расход — без НДС (как отдаёт Директ), рядом — с НДС 22 % (`VAT_PERCENT`).

## Как заявка находит своё объявление

Метки в объявлениях клиента не меняем — скрипт понимает любые. По порядку, первое сработавшее:

1. **Правило** с листа «Сопоставление меток»: «utm_campaign содержит spring → ID объявления 123…».
2. **ID**: в utm-метках или в адресе входа есть номер объявления, группы или кампании из Директа
   (например, `utm_content={ad_id}`, `utm_campaign={campaign_id}`, `…|{gbid}|…`). Объявление само
   определяет группу и кампанию.
3. **Название**: utm_campaign = название кампании; utm_content / utm_term = название группы.

Остальное: метка `utm_source` похожа на Яндекс (`DIRECT_SOURCE`) или есть `yclid` → «Директ, не сопоставлено»
(учитывается в итогах отдельной строкой); другой utm_source → «Другой источник»; ничего нет → «Без меток».

После подключения откройте лист **«Заявки»**: в колонке «Как сопоставлено» видно, что получилось, а в
колонках utm — какие метки на самом деле приходят. Для непонятых меток добавьте правило — отчёт пересчитается
при следующем обновлении или пунктом **Отчёт → Пересчитать отчёт**.

## Установка

1. Создайте Google Таблицу → **Расширения → Apps Script**. **Не вставляйте весь код в один `Код.gs`**:
   редактор обрезает длинную вставку (`SyntaxError: Unexpected identifier`). Создайте 9 отдельных файлов
   (**Файлы → + → Скрипт**, имя без `.gs`) и вставьте в каждый код одноимённого файла — со страницы
   [«Код отчёта Директ + Тильда»](https://claude.ai/artifact/FgNKRZLWu8YZAYCWJ2UcQn) (кнопка «Скопировать код» у каждого файла) или с raw-страниц (Cmd+A → Cmd+C):
   [`1_main`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/1_main.gs),
   [`2_util`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/2_util.gs),
   [`3_direct`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/3_direct.gs),
   [`4_tilda`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/4_tilda.gs),
   [`5_match`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/5_match.gs),
   [`6_report`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/6_report.gs),
   [`7_tables`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/7_tables.gs),
   [`8_setup`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/8_setup.gs),
   [`9_import`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/direct-tilda/9_import.gs).
   Порядок файлов не важен. Сохраните (Cmd+S).
2. Обновите таблицу — появится меню **Отчёт**. **Отчёт → Создать / обновить листы** (Google попросит разрешения).
3. **Директ.** Нужен OAuth-токен с доступом к API Директа на логин клиента: в Директе подайте заявку на доступ
   к API (**Инструменты → API**), на [oauth.yandex.ru](https://oauth.yandex.ru) создайте приложение с правом
   «Использование API Яндекс Директа», откройте `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>`
   под логином клиента и скопируйте токен. **Отчёт → Токен Яндекс Директа** → вставьте (логин — только для агентского токена).
   Затем **Отчёт → Загрузить данные из Директа** — первая загрузка за 180 дней (`INITIAL_DAYS`).
4. **Тильда.** В Apps Script: **Начать развертывание → Новое развертывание → Веб-приложение**, запуск от имени «Меня»,
   доступ «Все». **Отчёт → Подключить Тильду** покажет адрес вебхука с ключом и код для сайта:
   - Тильда → **Настройки сайта → Формы → Webhook** → адрес, отметьте «Передавать Cookies» → в каждой форме отметьте этот вебхук;
   - код для сайта → **Настройки сайта → Ещё → HTML-код для вставки внутрь HEAD**, опубликуйте все страницы
     (в заявку попадёт адрес входа с метками Директа — даже если человек оставил заявку на другой странице).
   Проверка: **Отчёт → Тестовая заявка** (строку потом удалите).
5. **Отчёт → Включить автообновление** — каждый день около **01:00 по Москве** загружаются данные Директа по вчера
   (последние 3 дня — заново) и пересчитывается отчёт. Заявки с Тильды приходят сразу, в отчёт — при пересчёте.

## Заявки, пришедшие до подключения вебхука

1. В Тильде: проект → вкладка **«Заявки»** → **«Экспорт»** (CSV или Excel) за нужный период
   (если заявки ведутся в Tilda CRM — выгрузка из CRM).
2. В таблице откройте лист **«Импорт Тильды»** (если его нет — выберите пункт меню из шага 3, он создаст лист) →
   **Файл → Импорт → Загрузить** файл → «Заменить текущий лист».
3. **Отчёт → Импортировать заявки из Тильды (выгрузка)**. Колонки находятся по названиям (дата, ID заявки, форма,
   имя, телефон, email, utm_*, страница); заявки, которые уже есть, пропускаются; привязка к объявлениям — как у новых.

## Безопасность

- Токен Директа и ключ вебхука хранятся только в Свойствах скрипта; в коде и на листах их нет.
- Вебхук принимает заявки только с ключом `?key=…`; заявка с тем же ID Тильды не дублируется.
- В «Заявках» — персональные данные (имя, телефон). Доступ на редактирование — только доверенным людям.

## Проверка без Google

`node direct-tilda/test/run.js` — имитация Таблиц, Директа (отчёт + тексты объявлений) и заявок с 11 разными
вариантами меток: сверяет сопоставление каждой заявки и итоги всех листов с независимым подсчётом.
