# Сквозная аналитика школы мотокросса → Google Таблица

Скрипт Google Apps Script живёт внутри таблицы. Раз в сутки он сам забирает данные и
сводит их по каналам, кампаниям (`utm_campaign`), дням и месяцам:

```
VK Реклама ─┐
Яндекс Директ (в т.ч. посевы в Макс) ─┤  расход          ┌─ Сводка_каналы
Авито ─┤                               ├─→ fact ─→ формулы ┼─ Сводка_кампании
Реклама_вручную (Telegram, посевы) ─┘                    ├─ Сводка_месяцы (+ чистая прибыль)
амоCRM — лиды (UTM / источник / теги) ──→                ├─ Сводка_дни
Мой Класс — пробные, повторные, абонементы, оплаты ──→    └─ Дашборд (KPI + графики)
```

На дашборде по каждому каналу видно: **расход, лиды, цену лида, пробные (пришли),
повторные тренировки, абонементы, конверсии, выручку, ДРР и ROMI**, а по школе в целом —
**чистую прибыль**. Сервер не нужен.

## Листы

| Лист | Что это | Кто заполняет |
|---|---|---|
| `Дашборд` | период (B3:B4), KPI, таблица по каналам, графики | формулы |
| `Сводка_каналы` / `_кампании` / `_дни` | воронка за выбранный период | формулы |
| `Сводка_месяцы` | воронка по месяцам + прочие расходы + чистая прибыль | формулы |
| `Реклама_вручную` | расходы без API: Telegram Ads, посевы, блогеры, 2ГИС… | **вы** |
| `Расходы` | постоянные расходы по месяцам: аренда, ЗП тренеров, техника, топливо | **вы** |
| `Настройки` | правила каналов, типы абонементов, параметры | **вы** (один раз) |
| `fact` | все события в одном формате, по нему считаются сводки | скрипт |
| `raw_*` | сырые выгрузки из кабинетов и CRM | скрипт |
| `Лог` | когда что обновлялось и ошибки | скрипт |

## 1. Установка

1. Проверьте, что на Google Диске есть свободное место. Если хранилище заполнено, Google
   переводит таблицу в режим «только чтение», и скрипт падает с ошибкой
   «У вас нет разрешения на доступ к этому документу».
   Затем создайте Google Таблицу → **Расширения → Apps Script**.
2. **Не вставляйте весь код в один `Код.gs`**: редактор обрезает длинную вставку, и появляется
   ошибка вида `SyntaxError: Unexpected identifier`. Вместо этого создайте 10 отдельных файлов
   (**Файлы → + → Скрипт**, имя без `.gs`) и вставьте в каждый код одноимённого файла.
   Удобнее всего копировать с raw-страниц (Cmd+A → Cmd+C): [`00_config`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/00_config.gs), [`01_menu`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/01_menu.gs), [`02_util`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/02_util.gs), [`10_ads_vk`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/10_ads_vk.gs), [`11_ads_yandex_avito`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/11_ads_yandex_avito.gs), [`20_amo`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/20_amo.gs), [`30_moyklass`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/30_moyklass.gs), [`40_attribution`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/40_attribution.gs), [`50_setup`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/50_setup.gs), [`90_debug`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/laughing-gates-9lubop/moto-dashboard/90_debug.gs).
   Порядок файлов значения не имеет. Файл `Код.gs` удалите или очистите полностью. Сохраните (Cmd+S).
3. **Настройки проекта** (шестерёнка): часовой пояс `Europe/Moscow` (или ваш). В самой
   таблице (**Файл → Настройки**) поставьте тот же часовой пояс.
4. Обновите страницу таблицы — появится меню **Дашборд**.
5. **Дашборд → Создать / обновить листы**. Google попросит разрешения — дайте их.

> Если работаете через [clasp](https://github.com/google/clasp) — в папке есть `appsscript.json`,
> можно просто `clasp push`.

## 2. Ключи доступа

Вводятся через **Дашборд → Ключи доступа** и хранятся в Свойствах скрипта, не в коде.
После ввода ключа источник сразу загружается.

| Источник | Что нужно | Где взять |
|---|---|---|
| **VK Реклама** | токен на 24 ч или `client_id` / `client_secret` | как в [`vk-ads-to-sheets`](../vk-ads-to-sheets/README.md): токен — в кабинете; ключи API — у агентства/поддержки VK |
| **Яндекс Директ** | OAuth-токен (+ логины кабинетов, если аккаунт агентский или кабинетов несколько) | 1) в Директе: **Инструменты → API** — подайте заявку на доступ; 2) создайте приложение на [oauth.yandex.ru](https://oauth.yandex.ru) с правом «Использование API Яндекс Директа»; 3) откройте `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>` и скопируйте токен (живёт год) |
| **Авито** | `client_id` / `client_secret` | [avito.ru/professionals/api](https://www.avito.ru/professionals/api) |
| **амоCRM** | адрес аккаунта (`xxx.amocrm.ru`) и долгосрочный токен | **амоCRM → Настройки → Интеграции → Создать интеграцию → Внешняя** → вкладка «Ключи и доступы» → «Сгенерировать долгосрочный токен» |
| **Мой Класс** | API-ключ | **Мой Класс → Настройки → API** → создать ключ |

Источник без ключей просто пропускается — его можно подключить позже.

## 3. Первая загрузка

При первой загрузке берутся последние 180 дней, поэтому запускайте источники **по одному**
(лимит Apps Script — 6 минут на запуск): **Обновить рекламу**, **Обновить амоCRM**,
**Обновить Мой Класс**, затем **Пересобрать сводку**. Потом включите
**Дашборд → Включить ежедневное обновление**: реклама в 4:00, амоCRM в 5:00, Мой Класс в 6:00,
сводка в 7:00.

Каждое обновление заново забирает последние 30 дней (`LOOKBACK_DAYS`). Так подтягиваются смены
статусов, поздние оплаты, корректировки расходов и пропуски, пока токен был недействителен.

## 4. Настройка каналов (самое важное)

1. **Дашборд → Отладка → Поля сделок амоCRM**. На лист `debug` выпишутся все поля сделок с
   примерами значений, теги, воронки и статусы. Посмотрите, где у вас записан источник заявки:
   - поля `utm_source`, `utm_campaign`… (их заполняют формы сайта, Tilda, Марквиз, виджеты амо) —
     подхватятся автоматически;
   - поле-список «Источник» — впишите его точное название в параметр `AMO_SOURCE_FIELD`;
   - теги или отдельные воронки (например, интеграция с Авито ставит тег) — добавьте правила.
2. На листе **Настройки** в колонках A:C правила «поле содержит → канал». Срабатывает первое
   подходящее правило сверху вниз. Правила применяются и к лидам, и к расходам: например,
   `кампания | макс | Макс` выделит посевы в Макс из кабинета Яндекса в отдельный канал —
   и их расход, и лиды с этих кампаний.
3. **Названия каналов у расходов и лидов должны совпадать** (`VK Реклама`, `Яндекс Директ`,
   `Авито`, `Макс`, `Telegram`…), иначе ДРР и ROMI не сойдутся. Каналы на листе
   `Реклама_вручную` пишите так же.
4. Параметры (H:J): воронки амо, которые считаются лидами (`AMO_PIPELINES`), статусы-исключения
   вроде «Спам»/«Дубль» (`AMO_EXCLUDE_STATUSES`) и др.
5. **Отладка → Примеры данных Мой Класс**: проверьте, что у записей на занятия есть флаги
   `test` (пробное) и `visit` (пришёл), а у платежей — `optype` (`income` / `refund`).
   Типы абонементов (E:F): «название содержит → тип». Если правило не сработало, абонемент на
   1 занятие считается разовой (повторной) тренировкой, на несколько — абонементом.
6. **Отладка → Операции Авито за 7 дней**: посмотрите `operationType` списаний за продвижение и
   поправьте `AVITO_SPEND`, если там не «списание».

После правок настроек нажмите **Пересобрать сводку** — перезагружать данные не нужно.

**Совет.** Если UTM в амо сейчас нигде не пишутся, настройте передачу UTM из форм сайта в поля
сделки (в амо это стандартные поля `utm_*`) и ставьте в рекламе метки
`utm_source=vk|yandex|avito|telegram|max` и `utm_campaign={campaign_id}`. Скрипт сам заменит
ID кампании её названием из кабинета.

## Как считаются показатели

| Показатель | Формула |
|---|---|
| **Лиды** | сделки амо, созданные в периоде (без исключённых статусов) |
| **Канал клиента** | телефон ученика Мой Класс (нормализуется к `7XXXXXXXXXX`) ищется среди сделок амо; берётся канал **первой** сделки с определённым каналом (first touch). Если сделки нет — «Без заявки в амо» |
| **Пробные** | записи на пробное занятие, где ученик пришёл, — по дате занятия |
| **Повторные / Абонементы** | проданные в Мой Класс абонементы по типу — по дате продажи |
| **Выручка** | платежи Мой Класс: приход − возвраты (списания с баланса выручкой не считаются) |
| **ДРР** | расход на рекламу / выручка |
| **ROMI** | (выручка − расход) / расход |
| **Чистая прибыль** | выручка − реклама − прочие расходы (лист `Расходы`). Считается по школе в целом и по месяцам: постоянные расходы по каналам не делятся |

Период задаётся на дашборде в B3:B4 (по умолчанию — текущий месяц). Выручка и продажи относятся
к каналу, из которого клиент пришёл, **в тот день, когда они случились**: абонемент, купленный в
октябре клиентом с сентябрьской заявки, попадёт в октябрь.

## Проверка

- Локальные тесты логики и формул (Node.js 18+): `node moto-dashboard/test/run.js`.
- В таблице: сверьте расход за неделю на `Сводка_каналы` с кабинетами, число лидов — с амо,
  продажи и оплаты — с отчётами Мой Класс.

## Безопасность

Репозиторий публичный. Ключи — **только** в Свойствах скрипта, никогда не вставляйте их в код.
Доступ на редактирование таблицы — только доверенным людям (редакторы видят свойства скрипта),
клиенту для просмотра давайте права «Читатель». Если ключ утёк — перевыпустите его в сервисе и
введите заново через меню. Подробнее — в разделе «Безопасность» [`vk-ads-to-sheets`](../vk-ads-to-sheets/README.md).
