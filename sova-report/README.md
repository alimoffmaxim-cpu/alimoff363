# Отчёт «Сова»: VK Реклама (3 кабинета) → Google Таблица

1 кабинет VK Рекламы = 1 направление клиники. В одной таблице:

| Лист | Что на нём |
|---|---|
| **Сводная** | Итог по всем направлениям: KPI месяца против тех же дней прошлого, таблица направлений с долей бюджета. **Свой период**: даты «Период с … по …» в H3 и J3 (двойной щелчок — календарь); тогда KPI и таблица направлений считаются за него и сравниваются с предыдущим периодом той же длины, пустые поля — текущий месяц. **Тенденция подписок** по завершённым неделям и месяцам — с первой недели / месяца, где есть данные (расход, показы, клики или подписки), до последнего завершённого — **вся история**, старые недели и месяцы не уходят (подписи с годом: «21.09–27.09.2026», «Сентябрь 2026»); скрипт перестраивает блок после каждой загрузки (в xlsx-шаблоне — всегда 26 недель и 12 месяцев). По направлениям и всего, изменение к прошлому периоду, средний тренд в % за неделю / месяц (с 4 периодов). Цена подписки и расход по направлениям. 6 графиков в колонку справа от таблиц, под подписками — расход за те же периоды: по неделям, по месяцам (вся клиника, с линией тренда); ниже подписки по направлениям по неделям и месяцам |
| **Направление 1/2/3** | Дневная статистика одного кабинета (итог всех кампаний): KPI периода; **постоянные таблицы по неделям и по месяцам** (все метрики и строка «Разница с прошлой неделей / месяцем»; меняются только после загрузки данных, выбор периода их не трогает); **детализация по дням** с днём недели. Период — поля «Период с … по …», как на «Сводной», пусто — текущий месяц. Таблица по дням и 3 графика в колонку (подписки, под ними расход по дням — с линией тренда; цена подписки по дням) показывают ровно дни этого периода: скрипт перестраивает их, когда меняются даты в полях и после каждой загрузки данных (до 400 дней; в xlsx-шаблоне — до 92) |
| **⚙ Настройки** | Направления (подставляются во все листы и графики), статус подключения кабинетов, отчётная дата |
| **Данные** | 1 строка = 1 день одного направления: дата, направление, расход, показы, клики, подписки |

Все листы отчёта считаются **формулами из листа «Данные»**: появились новые строки,
и цифры, подсветка цены подписки и графики обновились сами. Отчётная дата — последний день в «Данных».
Весь отчёт строит сам скрипт пунктом меню, xlsx-шаблон не нужен.

Ключевая цель кампаний — **вступления в сообщество (подписки)**. Метрики: CTR = клики / показы,
CPC = расход / клики, цена подписки = расход / подписки, CR в подписку = подписки / клики. Неделя — с понедельника по воскресенье; в тенденции участвуют только завершённые недели и месяцы, чтобы неполный текущий период не занижал тренд. «Этот месяц» — с 1-го
числа по отчётную дату, сравнение — с теми же днями прошлого месяца (▲/▼ зелёным, когда
изменение к лучшему: для цены подписки и CPC хорошо, когда они падают).

## Подключение

### 1. Таблица и скрипт

1. Создайте пустую Google Таблицу (или откройте ту, что уже лежит на Диске).
2. **Расширения → Apps Script**. **Не вставляйте весь код в один `Код.gs`**: редактор обрезает длинную
   вставку, и появляется ошибка вида `SyntaxError: Unexpected identifier`. Создайте 11 отдельных файлов
   (**Файлы → + → Скрипт**, имя без `.gs`) и вставьте в каждый код одноимённого файла.
   Удобнее всего — со страницы [«Код отчёта «Сова»»](https://claude.ai/artifact/HaCzXDMetXXrG3ynRvkr24):
   у каждого файла имя и кнопка «Скопировать код». Или с raw-страниц (Cmd+A → Cmd+C):
   [`1_main`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/1_main.gs), [`2_settings`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/2_settings.gs), [`3_api`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/3_api.gs), [`4_sync`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/4_sync.gs), [`5_debug`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/5_debug.gs), [`6_connect`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/6_connect.gs), [`7_build`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/7_build.gs), [`8_build_blocks`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/8_build_blocks.gs), [`9_build_periods`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/9_build_periods.gs), [`10_build_sheets`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/10_build_sheets.gs), [`11_days`](https://raw.githubusercontent.com/alimoffmaxim-cpu/alimoff363/claude/kind-cannon-kebl4w/sova-report/11_days.gs).
   Порядок файлов значения не имеет. Файл `Код.gs` удалите или очистите полностью. Сохраните (Cmd+S).
3. **Настройки проекта** (шестерёнка) → часовой пояс `Europe/Moscow`.
4. Обновите страницу таблицы — появится меню **Сова**.
5. **Сова → Создать / пересобрать отчёт**. При первом запуске Google попросит разрешения для скрипта.
   Скрипт сам выставит региональные настройки «Россия», часовой пояс Москвы и построит все листы,
   формулы, оформление и графики. Если лист «Данные» пуст, он предложит заполнить его демо-цифрами за год.
6. На листе **⚙ Настройки** впишите названия направлений в колонку A (например, «Стоматология») и
   снова нажмите **Создать / пересобрать отчёт**: листы направлений получат эти названия.
   Пересборка не трогает «Данные», токены и колонки B–D листа настроек. Направлений может быть сколько угодно, не только 3.

Запасной путь — готовый шаблон [`sova-report.xlsx`](sova-report.xlsx) с демо-данными: Google Диск →
**Создать → Загрузить файл** → **Файл → Сохранить как Google Таблицу**, затем шаги 2–4.

### 2. Автозагрузка из VK

1. **Сова → Удалить все строки с листа «Данные»**, если там демо-цифры.
2. Подключите каждый кабинет: **Сова → Ввести токен кабинета (из eLama)** → номер направления →
   токен. Кабинеты ведутся через eLama: она выдаёт постоянный токен API отдельно на каждый кабинет
   после подтверждения с контактной почты аккаунта (инструкция для клиента — [`ИНСТРУКЦИЯ_КЛИЕНТУ.md`](ИНСТРУКЦИЯ_КЛИЕНТУ.md)).
   Статус появится в колонке B листа настроек. Если вместо токена выдали `client_id` и
   `client_secret` — пункт меню **Подключить кабинет по client_id / secret**.
3. **Сова → Загрузить новые данные из VK** — первая загрузка за 365 дней.
4. **Сова → Включить ежедневное обновление** — каждое утро около 7:00 скрипт дописывает
   вчерашний день и перезагружает последние 3 дня (VK досчитывает конверсии задним числом).
   Если один кабинет не загрузился, остальные всё равно обновятся, а Google пришлёт письмо с ошибкой.

Графики строятся встроенными графиками Google Таблиц, линия тренда — линейная (в настройках графика:
«Серии → Линия тренда»).

## Настройки (`SOVA` в начале `1_main.gs`)

- `LEADS_METRIC` — какая метрика VK считается подписками (по умолчанию `base.vk.result` — результат по цели кампании, для кампаний на вступления это и есть вступления). Для
  отдельного кабинета её можно указать в колонке C листа настроек. Подобрать: запустите в
  редакторе `debugVkMetrics` — на лист `VK debug` выпишутся все метрики первого направления за 7 дней.
- `INITIAL_DAYS`, `REFRESH_DAYS`, `TRIGGER_HOUR` — глубина первой загрузки, сколько дней
  перезагружать, час ежедневного запуска.
- `TRENDS_FROM` — с какой недели начинать таблицы по неделям и месяцам на «Сводной» и листах
  направлений (сейчас `2026-09-21`); пусто — с первой недели, где есть данные.
- История недель и месяцев считается из листа «Данные», поэтому **не удаляйте строки «Данных»**
  после начала работы: из VK заново загружается только `INITIAL_DAYS` (365) дней.

## Как пересобрать xlsx-шаблон

Скрипт (`7_build.gs`–`11_days.gs`) и `tools/build_xlsx.py` строят один и тот же отчёт; меняете
оформление — меняйте в обоих. `tools/build_xlsx.py` собирает `sova-report.xlsx` (нужен `openpyxl`):
`python3 tools/build_xlsx.py sova-report.xlsx`. Число направлений в шаблоне — 3 (`DIRS`).

## Безопасность

- Репозиторий публичный: **никаких ключей в коде**. `client_id` / `client_secret` и токены
  хранятся только в Свойствах скрипта (вводятся через меню), в ошибках длинные строки маскируются.
- Права на **редактирование** таблицы — только доверенным людям (редакторы видят свойства
  скрипта). Клиенту для просмотра — доступ «Читатель».
- Токен eLama **бессрочный** — это ключ к статистике кабинета. Не пересылайте его в общих чатах.
  Утёк — попросите eLama отозвать его и выдать новый, затем введите новый через меню.
