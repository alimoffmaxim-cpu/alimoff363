# Выгрузка статистики VK Реклама → Google Таблица

Скрипт Google Apps Script живёт прямо внутри таблицы, раз в сутки забирает
статистику из [ads.vk.com](https://ads.vk.com) и записывает её на лист `VK Ads`.
Сервер не нужен.

## 1. Скрипт в таблице

1. Создайте Google Таблицу → **Расширения → Apps Script**.
2. Вставьте содержимое файла [`Code.gs`](Code.gs) вместо шаблонного кода, сохраните.
3. **Настройки проекта** (шестерёнка) → проверьте **часовой пояс** (например, `Europe/Moscow`).
4. Обновите страницу таблицы — появится меню **VK Реклама**.

## 2. Режим А: разовый токен на 24 часа (агентский кабинет)

1. Получите токен в кабинете VK Реклама.
2. В таблице: **VK Реклама → Ввести токен VK (на 24 ч)** → вставьте токен.
   Скрипт сохранит его в Свойствах скрипта (не в коде) и сразу выгрузит статистику.
   При первом запуске Google попросит разрешения — дайте их.
3. Один раз: **VK Реклама → Включить ежедневное обновление**.

Пока токен жив, данные обновляются автоматически. Когда он истечёт, ежедневный
запуск завершится ошибкой (Google пришлёт письмо о сбое триггера). Просто введите
новый токен: скрипт **сам догрузит все пропущенные дни** с последней даты на листе,
так что вводить токен можно хоть раз в неделю — данные не потеряются.

## 3. Режим Б: полная автоматика без ручного ввода

Для этого нужны ключи API (`client_id` / `client_secret`). В агентском кабинете их
выдаёт агентство: попросите менеджера агентства или поддержку VK Реклама о доступе
к API. Получив ключи, добавьте в **Настройки проекта → Свойства скрипта**:

| Свойство | Значение |
|---|---|
| `VK_CLIENT_ID` | client_id |
| `VK_CLIENT_SECRET` | client_secret |
| `VK_AGENCY_CLIENT_NAME` | только если ключи агентские — имя (логин) вашего клиента в агентстве |

После этого токены скрипт получает и обновляет сам, ручной ввод больше не нужен.

## Настройки (`CONFIG` в начале `Code.gs`)

- `LEVEL` — `ad_plans` (кампании), `campaigns` (группы объявлений), `banners` (объявления).
- `DAYS_BACK` — сколько последних дней перезаписывается при каждом запуске
  (VK пересчитывает статистику задним числом). Более старые строки не трогаются.

Если появится ошибка о лимите токенов — выполните `deleteAllVkTokens` и запустите выгрузку снова.

## Безопасность: как не опубликовать ключи на GitHub

Этот репозиторий **публичный** — всё, что в него попало, видно всем (и остаётся в истории коммитов даже после удаления файла).

- **Токены и ключи хранятся только в «Свойствах скрипта»** Apps Script, а не в коде.
  Токен вводится через меню таблицы, в `Code.gs` его нет — файл можно спокойно коммитить.
- **Никогда не вставляйте ключи в код «на время»**: при следующем копировании
  кода в репозиторий они уйдут в публичный доступ.
- `.gitignore` в корне не даёт закоммитить типичные файлы с секретами
  (`.env`, `credentials*.json`, `.clasprc.json` и т. п.) — секреты, если нужно
  хранить локально, кладите только в такие файлы.
- На GitHub: **Settings → Code security → Secret scanning / Push protection** —
  держите включёнными, GitHub заблокирует push с распознанным ключом.
- Доступ на **редактирование** таблицы давайте только доверенным людям: редакторы
  видят свойства скрипта. Для просмотра данных делитесь с правом «Читатель».
- **Если ключ всё-таки утёк** (попал в коммит, чат, скриншот) — удаления из репозитория
  недостаточно. Разовый токен сам умрёт через 24 часа, но лучше сразу получить
  новый. Если утёк client_secret — попросите перевыпустить ключи, выполните
  `deleteAllVkTokens` и обновите `VK_CLIENT_SECRET` в свойствах скрипта.
